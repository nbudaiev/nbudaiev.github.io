Which CASA version to use

Why "validated"?

The ALMA CASA + pipeline release comes once a year, at the start of an ALMA Cycle, after extensive tests on past, present and future ALMA data. ALMA recommends it for calibrating and imaging ALMA data.

ConceptCASA 6.7.4 and pipeline 2026

What is new in CASA and the pipeline

Theme: support and bug fixes

CASA 6.7.4 focuses on user support, maintenance and bug fixes. With RADPS (the software that will follow CASA for ALMA) ramping up, CASA is moving to maintenance mode with few new features.

New tools

iclean: a new task for interactive cleaning on Mac and Linux, with preliminary Jupyter support (Part 4, continuum imaging, follow-along). simalma/simobserve: a correlator parameter (e.g. 'BLC', 'BLC_4x4bit') sets which correlator efficiency a simulation uses.

Bug fixes

tclean no longer prints a SEVERE message about WEIGHT_SPECTRUM and POINTING (the images were fine). applycal(interp='linearPD') now unwraps phases that cross ±180°, and mosaics with deconvolver='mtmfs', nterms=1 work.

Pipeline 2026 (weblog: Part 3, inspecting weblogs)

New stage hifa_findROI finds line regions quickly. hif_findcont is faster. QA scores were retuned, so many former yellow scores are now blue. The weblog adds the software environment, spectral resolution in MHz and km/s, zenith angle and date plots, and target-to-calibrator separations.

Conceptdata columns and flags
Calibration writes new data columns

  

    
    

      
The FLAG column
FLAG marks bad data, which tasks skip. flagdata saves a backup first (flagmanager lists and restores versions).

      
Weights
WEIGHT (1/σ²) sets how much each visibility counts. applycal(calwt=True) updates it. SIGMA (σ of the raw DATA) is unchanged. Imaging weights start here.

      
Disk space
Each extra column can double the size. split out what you need before imaging. twhya_calibrated.ms is such a split. Its DATA column already holds calibrated data.

Takeawayfirst look at any dataset
Five commands for a first look

  

    


VIS = 'twhya_calibrated.ms'
# on an MS restored by scriptForPI add ydatacolumn='corrected' to plotms
# 1. what is in the MS: fields, spws, scans, intents, antennas
listobs(vis=VIS, listfile='twhya_listobs.txt', overwrite=True)

# 2. uv coverage per field ('10000' and '1e9' mean: average everything)
plotms(vis=VIS, xaxis='u', yaxis='v', avgchannel='10000',
       avgtime='1e9', coloraxis='field')

# 3. amplitude vs time, all fields: anything missing or jumping?
plotms(vis=VIS, xaxis='time', yaxis='amp', avgchannel='10000',
       coloraxis='field')

# 4. amplitude vs uv distance: point-like or resolved? outliers?
plotms(vis=VIS, field='5', xaxis='uvwave', yaxis='amp',
       avgchannel='10000', avgtime='1e9', coloraxis='antenna1')

# 5. target spectrum: lines? bad edge channels?
plotms(vis=VIS, field='5', xaxis='channel', yaxis='amp',
       avgtime='1e9', avgscan=True, avgbaseline=True)

    

    

      
From listobs, write down
Field IDs (0 and 6 bandpass, 2 Ceres for flux, 3 phase calibrator, 5 TW Hya), spw 0 with 384 channels, 6.05 s integrations, 19 antennas, ≈31 min on TW Hya.

      
From plotms, expect
Point-source calibrators flat in amplitude vs uv distance (Ceres is resolved and falls), phases near zero, no antenna or scan far off the rest.

Conceptlooking ahead
The Wideband Sensitivity Upgrade (WSU)

  

    

      
WSU: at least twice the bandwidth
The upgrade widens ALMA's system bandwidth by at least 2× with better sensitivity (ALMA memo 621). Data volumes grow massively, so the pipeline must get faster without losing science.

      
CASA + pipeline, then RADPS
WSU data will run through CASA and the pipeline until RADPS-ALMA (Radio Astronomy Data Processing System) replaces them, around 2031. Replacement starts from the end, with imaging first. CASA keeps calibration and self-calibration.

    

    

      
The imaging refactor
Goals: use the minimum data and the cheapest methods that still work, better throughput, products that lose less science, and code that carries over to RADPS.

      

        
ReleasePlanned (tentative)

        
PL2026Groundwork: new mstransform with LSRK transform, *_imaging MS, fftshift fixed in CASA, first hifa_findROI, faster findcont

        
PL2027fftshift in the pipeline, findROI feeding self-cal, new imageprecheck, smarter mitigation, binning before imaging

Untar the file in qa/ and open index.html. Check QA scores, flagging percentages, calibrator plots and the image rms before you download raw data.

Four questions on the TW Hya data

  
    
    
  1. twhya_calibrated.ms has 68,335 rows, one spw of 384 channels and 2 correlations. How big is one data column?
    Answer68,335 × 384 × 2 ≈ 5.2 × 10⁷ complex values × 8 bytes ≈ 0.42 GB. A modern dataset is about 300 times more.
    2. 
    
  2. Which selection keeps only TW Hya and leaves out the N2H+ line (channels 240–280)?
    Answerfield='5', spw='0:0~239;281~383'.
    3. 
    
  3. J1037-295 is flat in amplitude vs uv distance, but Ceres drops to zero near 300 kλ. Is something wrong?
    AnswerNo. J1037-295 is a point source. Ceres is a 0.8″ disk that the longer baselines resolve. Its flux model includes that.
    4. 
    
  4. intent='*PHASE*' also selected scans 4, 7 and 33. Why?
    AnswerThe bandpass (4, 33) and flux (7) scans carry CALIBRATE_PHASE too. Use field='3' for J1037-295 only.
